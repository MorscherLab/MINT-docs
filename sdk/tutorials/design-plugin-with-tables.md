# Tutorial 3 — Design Plugin With Tables

Build **panel-designer**, a standard experiment-design plugin that stores reusable drug panels in its own table. Users can create, list, replace, and delete their own panels, then publish a panel into a visible MINT experiment's design data.

This tutorial targets **MINT / mint-sdk 1.2.6** and uses the Alembic opt-in introduced in 1.2.2: `get_migration_spec()` returns a `MigrationSpec`. Existing plugins can retain the [legacy integer migrations](/sdk/concepts/migrations#existing-plugins-with-integer-migrations); do not declare both migration protocols on one plugin.

**Prerequisites:** [Tutorial 2](/sdk/tutorials/adding-a-frontend), Python with the SDK installed, and a disposable MINT instance for the final PostgreSQL check.

## 1. Scaffold and declare dependencies

```bash
mint init panel-designer --name "Panel Designer" \
  --description "Reusable drug panels and experiment designs" \
  --mode standard --type experiment-design --yes
cd panel-designer
uv add 'mint-sdk[local-db]>=1.2.6,<1.3'
```

The SDK's `local-db` extra supplies compatible SQLModel, SQLAlchemy, aiosqlite, greenlet, and Alembic dependencies. Keep the scaffold's package metadata and sole `mint.plugins` entry point. The examples below use `src/mint_plugin_panel_designer/`; use your scaffold's package path if it differs. Keep the frontend and packaging files generated by `mint init`.

There are three independent versions:

| Value | Meaning |
|---|---|
| Built plugin package version | Version derived from Git by the scaffold's `hatch-vcs` configuration; recorded in wheel metadata |
| `@mint_plugin(schema_version="1.0")` | Version recorded with published design data |
| Alembic `revision = "p001"` | String revision in the plugin-owned SQL migration chain |

Changing one does not update the other two. See [Migrations](/sdk/concepts/migrations).

## 2. Define the current table

Create `src/mint_plugin_panel_designer/models.py`:

```python
from uuid import uuid4

import sqlalchemy as sa
from sqlmodel import Field, SQLModel


class Panel(SQLModel, table=True):
    __tablename__ = "panels"

    id: str = Field(default_factory=lambda: str(uuid4()), primary_key=True, max_length=36)
    owner_user_id: str = Field(index=True, max_length=255)
    name: str = Field(max_length=200)
    drugs: list[dict[str, object]] = Field(sa_column=sa.Column(sa.JSON, nullable=False))
```

The application generates UUID strings, so inserts work with the same model and migration on SQLite and PostgreSQL without backend-specific identity-column DDL. `owner_user_id` comes from the authenticated SDK actor; it is never accepted from a request body.

Do not set `__table_args__ = {"schema": "public"}` or hard-code a plugin schema in the model. MINT scopes the integrated session to the plugin's schema; standalone SQLite uses unqualified tables. Keep foreign keys between plugin-owned tables. Resolve platform experiment IDs through the SDK repository instead of importing platform ORM models or adding a cross-schema foreign key.

## 3. Add CRUD and experiment publishing

Replace `src/mint_plugin_panel_designer/plugin.py`:

```python
from typing import Annotated

from fastapi import HTTPException
from pydantic import BaseModel, ConfigDict, Field
from sqlalchemy.ext.asyncio import AsyncSession
from sqlmodel import select

from mint_sdk import (
    AnalysisPlugin,
    CurrentExperiment,
    CurrentPluginActor,
    PluginCapabilities,
    PluginType,
    endpoint,
    mint_plugin,
)
from mint_sdk.migrations import MigrationSpec
from mint_plugin_panel_designer.models import Panel


class Drug(BaseModel):
    name: str = Field(min_length=1, max_length=200)
    doses_uM: list[Annotated[float, Field(ge=0, allow_inf_nan=False)]] = Field(min_length=1, max_length=100)


class PanelInput(BaseModel):
    name: str = Field(min_length=1, max_length=200)
    drugs: list[Drug] = Field(min_length=1, max_length=100)


class PanelOutput(PanelInput):
    model_config = ConfigDict(from_attributes=True)
    id: str


@mint_plugin(
    analysis_type="drug-response",
    routes_prefix="/panel-designer",
    plugin_type=PluginType.EXPERIMENT_DESIGN,
    capabilities=PluginCapabilities(
        requires_auth=True,
        requires_shared_database=True,
        requires_experiments=True,
    ),
    schema_version="1.0",
)
class PanelDesignerPlugin(AnalysisPlugin):
    def get_shared_models(self) -> list[type]:
        return [Panel]

    def get_migration_spec(self) -> MigrationSpec:
        return MigrationSpec(
            package="mint_plugin_panel_designer.migrations",
            models=(Panel,),
        )

    async def _owned_panel(
        self, session: AsyncSession, panel_id: str, user_id: str
    ) -> Panel:
        result = await session.execute(
            select(Panel).where(Panel.id == panel_id, Panel.owner_user_id == user_id)
        )
        panel = result.scalar_one_or_none()
        if panel is None:
            raise HTTPException(status_code=404, detail="Panel not found")
        return panel

    @endpoint.get("/panels", response_model=list[PanelOutput])
    async def list_panels(self, actor: CurrentPluginActor) -> list[PanelOutput]:
        async with self.get_plugin_db_session() as session:
            result = await session.execute(
                select(Panel).where(Panel.owner_user_id == actor.user_id).order_by(Panel.id)
            )
            return [PanelOutput.model_validate(panel) for panel in result.scalars()]

    @endpoint.post("/panels", response_model=PanelOutput, status_code=201)
    async def create_panel(
        self, body: PanelInput, actor: CurrentPluginActor
    ) -> PanelOutput:
        panel = Panel(owner_user_id=actor.user_id, **body.model_dump(mode="json"))
        async with self.get_plugin_db_session() as session:
            session.add(panel)
            await session.flush()
            return PanelOutput.model_validate(panel)

    @endpoint.put("/panels/{panel_id}", response_model=PanelOutput)
    async def replace_panel(
        self, panel_id: str, body: PanelInput, actor: CurrentPluginActor
    ) -> PanelOutput:
        async with self.get_plugin_db_session() as session:
            panel = await self._owned_panel(session, panel_id, actor.user_id)
            panel.name = body.name
            panel.drugs = body.model_dump(mode="json")["drugs"]
            await session.flush()
            return PanelOutput.model_validate(panel)

    @endpoint.delete("/panels/{panel_id}")
    async def delete_panel(self, panel_id: str, actor: CurrentPluginActor) -> dict[str, bool]:
        async with self.get_plugin_db_session() as session:
            panel = await self._owned_panel(session, panel_id, actor.user_id)
            await session.delete(panel)
        return {"deleted": True}

    @endpoint.post("/experiments/{experiment_id}/panels/{panel_id}/publish")
    async def publish_panel(
        self,
        panel_id: str,
        experiment: CurrentExperiment,
        actor: CurrentPluginActor,
    ) -> dict[str, object]:
        if not actor.has_permission("experiments.edit"):
            raise HTTPException(status_code=403, detail="Missing permission: experiments.edit")
        async with self.get_plugin_db_session() as session:
            panel = await self._owned_panel(session, panel_id, actor.user_id)
            snapshot = PanelOutput.model_validate(panel).model_dump(mode="json")
        saved = await self.save_design(experiment.id, {"panel": snapshot})
        if saved is None:
            raise HTTPException(status_code=503, detail="Design repository is unavailable")
        return {"published": True, "experiment_id": experiment.id, "panel_id": panel_id}
```

`requires_auth=True` makes integrated routes use platform authentication. It does **not** add row ownership to custom tables: the owner predicate above is essential. Standalone mode uses the explicit single-user actor `standalone`; it is a local development mode, not a multi-user authentication service.

`CurrentExperiment` resolves a visible, compatible experiment through the platform and requires `experiments.view`. The publishing route separately checks `experiments.edit`. `EXPERIMENT_DESIGN` supplies the plugin's default design-write capability; a user permission and a plugin capability serve different purposes.

The panel table stores reusable drafts. `save_design()` publishes a snapshot through the platform's design repository. This replaces the experiment's design payload with `{"panel": ...}`; if your design contains other sections, load and deliberately merge them first. Updating or deleting a draft does not change previously published snapshots. Publishing needs a real platform context and returns 503 in standalone mode.

The session commits on successful context exit and rolls back on an exception. `flush()` sends pending writes while the session is open; response models are built before leaving it. There is no transaction spanning a plugin table write and `save_design()`, which is why publishing is a separate action here.

## 4. Declare the initial migration

Create `src/mint_plugin_panel_designer/migrations/__init__.py` as an empty file, then `migrations/p001_initial.py`:

```python
from alembic import op
import sqlalchemy as sa

revision = "p001"
down_revision = None
branch_labels = None
depends_on = None
destructive = False


def upgrade(*, schema: str | None) -> None:
    op.create_table(
        "panels",
        sa.Column("id", sa.String(36), primary_key=True),
        sa.Column("owner_user_id", sa.String(255), nullable=False),
        sa.Column("name", sa.String(200), nullable=False),
        sa.Column("drugs", sa.JSON, nullable=False),
        schema=schema,
    )
    op.create_index("ix_panels_owner_user_id", "panels", ["owner_user_id"], schema=schema)


def downgrade(*, schema: str | None) -> None:
    raise NotImplementedError("Use a reviewed forward migration or restore a backup")
```

Alembic revisions use **synchronous** `upgrade(*, schema)` functions; do not copy the legacy async `PluginMigration.upgrade(op)` signature. MINT supplies the connection and active schema: `None` for SQLite, the plugin's schema for PostgreSQL. Pass it to every table/index operation. No plugin-owned `env.py` or `alembic.ini` is needed.

Keep `get_shared_models()` for the SDK's existing model surface and declare the same models in `MigrationSpec.models` for migration comparison. Do **not** keep `get_migrations_package()`: the two migration declarations are mutually exclusive.

On a fresh SQLite or in-process PostgreSQL database, this baseline really executes. MINT does not create the table from the current model first and does not silently stamp the new protocol. It records the database owner, revision, and revision-file checksum. Existing unversioned tables require an explicit reviewed [baseline adoption](/sdk/concepts/migrations#adopting-existing-tables).

## 5. Verify persistence and ownership

Add `tests/test_panel_database.py`:

```python
from pathlib import Path

import pytest
from fastapi.testclient import TestClient
from mint_sdk import PluginActor
from mint_sdk.app import create_standalone_app
from mint_sdk.runtime_dependencies import current_plugin_actor

from mint_plugin_panel_designer.plugin import PanelDesignerPlugin


def test_panel_crud_and_owner_boundary(tmp_path: Path, monkeypatch: pytest.MonkeyPatch) -> None:
    plugin = PanelDesignerPlugin()
    # Explicit local storage: tests must not write to ~/.mint/plugins/.
    plugin._setup_standalone_db(storage_dir=tmp_path)
    monkeypatch.setattr(plugin, "get_frontend_dir", lambda: None)
    app = create_standalone_app(plugin, environ={})
    with TestClient(app) as client:
        base = "/api/panel-designer/panels"
        body = {"name": "Cisplatin", "drugs": [{"name": "Cisplatin", "doses_uM": [0.1, 1]}]}
        created = client.post(base, json=body)
        assert created.status_code == 201
        panel_id = created.json()["id"]
        assert client.get(base).json()[0]["id"] == panel_id
        assert client.put(f"{base}/{panel_id}", json={**body, "name": "Pilot"}).status_code == 200

        app.dependency_overrides[current_plugin_actor] = lambda: PluginActor(user_id="other")
        assert client.get(base).json() == []
        assert client.put(f"{base}/{panel_id}", json=body).status_code == 404
        assert client.delete(f"{base}/{panel_id}").status_code == 404
        app.dependency_overrides.clear()

        assert client.delete(f"{base}/{panel_id}").status_code == 200
        assert client.get(base).json() == []
        assert client.post(base, json={"name": "", "drugs": []}).status_code == 422
```

This tests standalone persistence and row authorization with explicit test actors. Add the [migration upgrade check](/sdk/recipes/backfill-migration#test-the-real-upgrade-path) to test historical data preservation in addition to this fresh-database path.

```bash
uv run pytest -q
mint doctor --strict
mint dev
```

Use the backend address printed by `mint dev`:

```bash
curl -X POST http://127.0.0.1:8003/api/panel-designer/panels \
  -H 'Content-Type: application/json' \
  -d '{"name":"Cisplatin","drugs":[{"name":"Cisplatin","doses_uM":[0.1,1,10]}]}'
curl http://127.0.0.1:8003/api/panel-designer/panels
```

For an installed platform test, authenticate through MINT, create a compatible experiment, and POST to `/api/panel-designer/experiments/{experiment_id}/panels/{panel_id}/publish`. Verify the saved design via the platform, repeat with a user lacking edit permission, and verify another user cannot modify the draft. `mint dev --platform` supplies a development proxy; it does not turn SQLite into the installed PostgreSQL database.

## 6. Evolve the schema and connect the frontend

When adding a field, update `Panel` **and add** a new revision whose `down_revision` names the current head. Keep `p001_initial.py` unchanged. Test an old populated database and a fresh database. See the [backfill recipe](/sdk/recipes/backfill-migration) for a complete `p002` revision and upgrade test.

Inspect an existing local development database after the first successful `mint dev` startup:

```bash
mint db current --path . --database-url "sqlite:///$HOME/.mint/plugins/panel-designer/data.db"
mint db check --path . --database-url "sqlite:///$HOME/.mint/plugins/panel-designer/data.db"
```

After changing the model, use `mint db revision "add panel notes" --path . --database-url <development-url>` to generate a draft **instead of** hand-writing that same revision. The development database must already be at the packaged head. Review generated operations and backfills before restarting the development runtime. If models already match, no revision file is created. These CLI commands do not apply, upgrade, or stamp a database.

Regenerate the TypeScript contract after editing endpoints:

```bash
mint sdk generate
mint docs contract .
mint build .
```

In the scaffolded Vue workspace, import `useGeneratedPluginClient` from `frontend/src/generated/mint-plugin.ts` and follow its generated signatures for `create_panel`, `list_panels`, and the other operation IDs. Use the contract output to determine method names and the `body`/`pathParams` wrapper; do not derive those names by guessing from the URL. Render controls with the [frontend SDK](/sdk/frontend/).

For deployment, this plugin must run **in-process** to access PostgreSQL. A plugin with `requires_shared_database=True` cannot use the installed remote subprocess context in v1.2.6. See [Isolation](/sdk/concepts/isolation), [Migrations](/sdk/concepts/migrations), and [Querying plugin data](/sdk/recipes/querying-plugin-data).
